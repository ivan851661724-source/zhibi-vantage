## 目录职责

- `architecture/`保存现行运行结构和技术约束，不重复定义产品承诺或领域状态。
- `spec/`保存基础领域规格与已批准的规格变更。仍在评审或专项验证的内容保留其状态，不因位于该目录而视为实现完成。
- `spec/01_Product_PRD_v1.5.0.md` 是唯一现行产品宪法；批准前评审资料移入 `history/`。
- `operations/`保存当前运行操作；`history/`保存需要追溯的过程记录，明确不参与当前规范优先级。

## 规范优先级

已批准的规格变更按其声明范围修订对应条款。除此之外，沿用工程基线、冻结产品需求、相关模块规格、工程任务、实现代码的业务语义优先级。现行架构和API资料说明兼容与运行情况，不能覆盖更高层的业务要求。

实现代码用于核对实际行为。发现实现与规格不同，应记录冲突、影响及选项，不能用“现在就是这样”把缺陷变成新规范。尚未冻结的供应商、阈值和市场范围由 SC、POC 与发布评审裁决，不得反向改写产品宪法。
