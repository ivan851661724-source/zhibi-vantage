# 03 · 迁移实施方案（原生 JS → Next.js）

> 原则：**行为等价、小步快跑、随时可回退**。后端（`app/`）零改动，只加不改。
> 依赖文档：[01-前端架构规范.md](./01-前端架构规范.md)、[02-API契约.md](./02-API契约.md)。

---

## 1. 迁移范围盘点

### 1.1 现状资产
| 资产 | 体量 | 去向 |
|---|---|---|
| `app/public/index.html` | 43KB，单页 + 7 面板 + 鉴权屏 | 拆为 App Router 路由（01 §4 映射表） |
| `app/public/app.js` | 272KB 单体 | 按面板拆分至各 page + components/hooks |
| `app/public/styles.css` | 98KB | 原样迁移为 `globals.css`，禁止顺带重写 |
| `app/public/js/api.js` | ZB_API 契约层 | 并入 `src/lib/api.ts`（注意其未实现端点，02 §4） |
| `app/public/mock/*.json` | 4 个 mock | 迁至 `web/public/mock/`，保留演示模式 |
| `app/lib/pricefield.js` 的 `parsePriceRange` | 价格解析单一实现 | 复制到 `web/src/lib/price.ts` + parity check（01 §6） |

### 1.2 不动的东西
- 后端全部代码、docker-entrypoint 播种逻辑、`zhibi_data` 数据卷。
- 旧前端在切换完成前**保留可运行**（回退通道）。

## 2. 迁移后部署拓扑

```
浏览器 ──→ zhibi-web（Next.js standalone，:3000）
              │ rewrites /api/* /metrics /healthz
              ▼
           zhibi-vantage（现有零依赖 Node，容器内 :3300，不再对宿主机暴露）
              │
              ▼ zhibi_data 卷（不变）
```

- 过渡期：`zhibi-vantage` 仍映射宿主机 3300（旧入口保活）；切换后移除该 ports 映射。
- Nginx/安全组：最终只对外 3000（或 80/443 反代），与 README 部署文档同步更新。
