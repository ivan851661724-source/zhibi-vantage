# 知彼 Vantage 前端架构规范

状态：现行前端架构约束。范围为`web/`，整体结构见[整体架构规范](00_整体架构规范.md)，接口兼容见[现行API契约](02_现行API契约.md)。原生静态前端迁移已成为历史，不再把`app/public/`当作现行入口。

## 1 技术选型

| 项目 | 选择与约束 |
|---|---|
| 框架 | Next.js App Router、React与TypeScript |
| 依赖 | 沿用react、react-dom、next；新增组件或状态依赖先说明必要性 |
| 样式 | 全局样式和CSS Modules；遵循[界面设计规范](03_界面设计规范.md)，避免无关视觉重写 |
| 请求 | 原生fetch经统一请求层，保留令牌、错误和状态语义 |
| 实时更新 | EventSource订阅后端事件，断线重连与轮询兜底 |
| 包管理 | pnpm及已提交锁文件 |

框架版本以`web/package.json`与锁文件为准。业务与鉴权行为的改动单独评审，不能作为整理目录或重构的附带变化。

## 2 目录结构

| 目录或文件 | 职责 |
|---|---|
| `web/next.config.ts` | 同源代理、安全响应头与standalone输出 |
| `web/src/app/` | 路由、布局及全局样式 |
| `web/src/components/` | 共享界面组件 |
| `web/src/hooks/` | 页面状态、研究进度与全局状态订阅 |
| `web/src/lib/api.ts` | 统一请求、鉴权和错误处理 |
| `web/src/lib/sse.ts` | 事件订阅、重连和事件分发 |
| `web/src/lib/price.js` | 与后端保持一致的价格解析 |
| `web/src/types/` | 接口与页面使用的类型 |
| `web/public/` | 当前静态资源，不恢复已经移除的旧演示副本 |

## 3 与后端连接

Next.js不建立第二套业务API。`/api/*`、`/healthz`和`/metrics`按当前配置代理到Node后端。开发默认后端地址为`http://127.0.0.1:3300`，容器内为`http://zhibi-vantage:3300`。

构建代理地址、监听方式和端口以`web/Dockerfile`及`docker-compose.yml`为准，见[部署与运行](../operations/01_部署与运行.md)。代理地址在构建中确定，不能只修改运行时变量就假定已有构建已更新。

沿用现行令牌存储和兼容键。401只有对应鉴权失败时才清理会话；供应商未配置等业务错误应在页面交付，不误登出。事件流的令牌和租户隔离按接口契约执行。

| 路由 | 用途 |

旧hash面板和旧app.js的行号不作为当前路由依据。新增路由先确认产品范围、权限和验收，再更新对应规格。

## 5 数据流与状态

`/api/state`是现行用户档案的主要聚合读取入口。事件通知驱动重新读取状态，比较后更新界面；断线时按现有订阅实现使用轮询兜底。服务端心跳和客户端兜底周期分别检查，不能混作同一指标。

全局业务状态不在组件中另建可变真相。业务修改经接口完成，再从权威读取结果刷新。筛选、折叠和临时选择等界面状态留在对应组件。请求经统一接口层处理，避免重复鉴权和错误分支。

面板继续沿用当前客户端交互方式。变更状态读取方式、服务端取数或令牌模型时，应同时评审权限、接口和兼容影响。

## 6 价格解析一致性

`web/src/lib/price.js`与`app/lib/pricefield.js`的`parsePriceRange`保持一致。任一侧调整时同步另一侧，并运行`node web/scripts/check-price-parity.mjs`的源码及行为检查。

当前不再通过旧index.html注入该函数。不得因迁移已结束而删除一致性验证，也不得用放宽检查替代修正漂移。

## 7 编码与变更要求

TypeScript保持严格检查。确需使用宽泛类型时说明原因；组件、工具和hooks沿用既有命名和布局。接口载荷、状态和错误语义的变化与类型、文档及验证同步交付。

按可评审的功能范围提交，不再套用已结束的逐面板迁移排期。源码引用使用当前路径及稳定符号；历史行号仅用于追溯。

## 8 验收要求

前端改动按范围运行构建、类型检查和价格一致性。保持原有性能及构建质量要求，不为通过检查禁用规则或忽略错误；既有警告和未运行项目如实报告。

原架构基线的构建零错误、零警告目标继续保留。存在存量警告时记录实际结果，不据此宣称已满足该目标。原有30秒内事件连接恢复目标也需通过对应断线恢复场景重新验证，不能以库自带重连代替验收。

接口或状态订阅变化还需检查同源请求、鉴权失败与业务错误分流、租户隔离、事件断线恢复及状态刷新。性能约束沿用已有页面预算，原首页脚本gzip小于300KB的预算应通过实际测量核验，不能引用旧app.js大小代替当前结果。
