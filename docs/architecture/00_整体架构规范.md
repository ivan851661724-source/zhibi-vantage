# 知彼 Vantage 整体架构规范

核查日期：2026-10-13。本文说明当前代码的运行结构和模块边界。产品承诺、数据语义及质量要求仍以[工程基线](../spec/00_Engineering_Baseline_v1.2.md)和其引用规格为准。实现现状不自动代表全部领域要求已经验收。

## 运行结构

浏览器通过Next.js前端访问产品。前端把业务请求和事件流转发给Node后端，后端负责鉴权、研究、采集、分析、调度和持久化。

```text
浏览器
  └─ Next.js 前端 web/，默认端口3000
       └─ /api/*、/healthz、/metrics 同源代理
            └─ Node API 后端 app/，默认容器内端口3300
                 ├─ 研究与采集 → 外部供应商、公开来源、可选内部搜索服务
                 └─ 持久化 → SQLite及现有文件存储，位于后端数据目录
```

依据为[编排文件](../../docker-compose.yml)、[前端配置](../../web/next.config.ts)、[数据库服务](../../app/services/db.js)及[档案存储](../../app/core/state-store.js)。当前默认编排不向宿主机暴露后端3300端口。可选搜索服务只在容器网络内使用，其启用条件和配置以编排及供应商配置为准。

旧的`app/public/`静态前端已移除，当前Web入口在`web/`。旧迁移过程见[历史记录](../history/2026-08-31_前端迁移记录.md)，不能据此恢复双入口、旧静态资源或旧镜像版本。

## 模块职责

| 位置 | 职责 | 边界 |
|---|---|---|
| `web/src/app/`、`components/` | 页面、交互和展示 | 不承担领域事实裁决，不另建业务API |
| `web/src/lib/`、`hooks/`、`types/` | 请求、事件订阅、状态和类型 | 沿用同源接口与鉴权契约，事件通知后重新读取权威状态 |
| `app/server.js`、`routes/`、`middleware/` | 请求入口、路由和身份检查 | 租户数据请求及事件按身份隔离 |
| `app/core/` | 配置、请求上下文、状态和基础服务 | 数据路径和租户上下文保持一致，不在新模块重复定义 |
| `app/research/` | 发现、采集、证据、事实、差分和研究任务 | 保留原始观测和失败，遵守数据与采信规格 |
| `app/lib/` | 价格、来源和其他计算工具 | 计算规则必须有规格及对应验收，不能用现存规则反向批准产品语义 |
| `app/services/` | 数据库、租户、额度及服务接口 | 保持兼容与权限边界，迁移另立方案 |
| `app/observability/`、`app/test/` | 可观测性与程序验证 | 日志和单测不替代独立真实数据质量评估 |

## 数据与业务边界

领域链沿用原始观测、证据、事实、指标、事件、判断的层次。数值必须能追到支持它的证据；业务事件还需可比的前后观测。来源失败、规格不匹配和历史不足不能转换为零或无变化。

公共品牌资料与用户工作空间的竞争关系分别管理。共享前核对品牌身份、市场、范围和新鲜度。用户价格、偏好、备注和判断不作为可共享公共资料。

当前`app/services/db.js`使用Node内置SQLite，研究档案等路径仍可见文件存储。本文不宣称已迁移到PostgreSQL，也不要求所有资料立即迁往单一数据库。存储迁移必须保持标识、证据引用、租户隔离与历史连续性，并具备回退和核对办法。

2026-10-17 M1增量接线：Shopify研究保留产品页与既有cart.js请求的原始快照，版本化提取真实可售字段及同域、同批、同项目币种证明，原Fact价格和Diff/Event含义保持。`app/research/price-metric.js`只从显式本批Fact派生目录样本分布，按租户写入DATA下不可变Metric文件，档案仅存精简引用/数值投影。失败、空页和partial范围与支持数值的快照分开保存；不扫描租户历史择最新值，不给旧item统计机械贴引用。API证明链安全投影见现行契约，实施与验收边界见[M1计划](../spec/plans/2026-10-17_M1_Fact_Metric.md)。

该增量不代表Canonical复用、Core Product Line、正式资格、监控消费或JudgmentSnapshot已接通。旧资格仍使用兼容路径，其全目录价格统计与基线的冲突已登记于[SCP-02](../spec/changes/SCP-02_runtime_PRD_conflicts.md)，不得因保留代码而视为批准。

## 前后端接口

现行客户端兼容接口见[现行API契约](02_现行API契约.md)。领域对象及计划中的正式合同见[后端与接口规格](../spec/03_Backend_API_Contract_v0.3.md)。两者分别说明实现兼容与领域目标，不可把计划端点当作现有端点调用，也不可把现有缺陷当作正式规则。

前端读取状态并订阅事件；事件流不另建第二份业务真相。价格解析保留前后端一致性检查。任何鉴权、错误语义、事件载荷或类型变化，应同时更新相关实现、接口文档及验证。

## 采集、调度和成本

研究任务可以按问题补查，日常巡检优先使用已知直接来源。无有效变化时不重跑完整研究。升级、重试和备用源调用有边界；必需检查未完成时保留可见缺口。

2026-10-17 M2新增可选正式路径：`app/services/monitoring-store.js`在DATA下使用独立`monitoring.db`（schema/user_version=1），保存Workspace、WatchTarget、幂等、队列、租约、cursor/gap及技术配置。旧数据库和研究档案不迁移、不删除。身份与资格只读集成格式必须有完整服务器证明链；本轮没有实现可信Canonical Brand或QualificationResult生产者，也不从旧done/S3推导准入。

`app/research/monitoring.js`和`monitoring-scheduler.js`按显式Workspace IANA时区的06/14/22窗口派发，持久入队后恢复、Workspace轮转、JOB级provider限流与租约均有界。晚到不超过十五分钟的当前窗口按原scheduled_at安排；超过边界的未入队窗口记录缺口，已观察的背压待办保留，不新增通用历史补跑政策。执行与提交前重验原始租户、准入、暂停、revision及lease；异步采集在事务之外，结果经同步fencing投影，不能承诺文件事实链与SQLite整体exactly-once。

正式路径只对已知Shopify目录调用现有Net及M1事实指标链，不触发发现或研究模型，不保存整包旧project。M3增量增加下述持久检查观察与站内事件投影，外部推送未启用。正式Net选项`rejectRedirects:true`保留已核验精确hostname，并阻止cart和产品请求自动跳转，3xx留存后失败，实际collector版本为`net-shopify-direct-2`；默认旧路径自动follow的既有风险仍开放。停止/暂停能阻止迟到结果进入当前投影，已经发出的HTTP尚无取消保证。

只有`FORMAL_MONITORING_ENABLED=1`才选择该路径；`SCHEDULER_ENABLED=0`仍全部关闭，默认保持旧scheduler。新增API提供配置、显式加入/暂停/恢复、同范围已支持价格事件的幂等复查及真实执行状态。来源市场无证明时仍为null，严格同市场复查拒绝这类实际事件且不外呼；合成带市场的正向回归不能替代真实接通。跨Workspace采集合并、公共事实复用及生产SLA仍未验收，M2整体PARTIAL，见[M2计划](../spec/plans/2026-10-17_M2_监控主链.md)。

2026-10-17 M3增量在同一monitoring.db保留核心user_version=1，通过独立扩展版本登记表安装`monitoring_coverage`与`monitoring_event_projections`，拒绝未知扩展版本，旧表/数据不删。Coverage目前只保存实际已提交job-attempt观察及其支持链，是完整窗口Coverage的输入；历史成员、P0映射、窗口、鲜度和actionability缺证明时保留null。quiet读取同一对象并守住100%门槛，当前生产输入不足时始终关闭，不以done、来源success或空事件替代。

runtime保留逐Fact比较诊断，正式引用核对原始scope、Evidence/Fact/Diff/Event内容和raw；站内投影复用现有价格解析及展示函数验证来源支持，合法部分扫描子集变化带限制显示为observed。目标品类关联不等于商品相关性/重要性已确认，来源market也不从Workspace补值。通知按原始tenant/workspace/target/event稳定去重，revision与投影版本仅作溯源。完成标记、Coverage、站内投影和当前结果在同一SQLite事务提交；Fact/Event文件不在该事务内，提交故障可能留下未补投Event，不承诺跨存储零丢失。

状态API增量返回两类持久历史及独立总数，不新增外部通知资格/偏好写入口、provider或调度器；旧alerts/digest保留。完整窗口生产者、自动日报/周报、外部投递outbox与生产质量仍为PARTIAL，详见[M3计划](../spec/plans/2026-10-17_M3_Coverage_quiet_通知.md)。
领域规定的监控时区、周期和窗口以[后端规格](../spec/03_Backend_API_Contract_v0.3.md)为准。当前实现是否满足这些要求应由实际测试和运行记录确认，不能仅凭本架构图宣称满足当天提醒或静默摘要承诺。

付费调用按相关对象和能力归因。缓存或公共资料复用不得刷新原始观察时间、扩大适用范围或泄露用户上下文。

## 部署与变更约束

部署操作见[部署与运行](../operations/01_部署与运行.md)。构建、监听地址、代理目标和端口以当前Dockerfile及编排文件为准；前端代理目标在构建阶段注入，不能只改运行时变量就假定旧构建已改变。

本次文档整理不切换架构、供应商、数据库或生产环境。新增业务状态、事实语义、调度承诺、资格规则或存储方案时，先处理对应产品决策和规格变更，再实施。

## 验证

按变更范围运行后端测试、前端价格一致性、类型检查及构建。接口和部署变更还需要验证同源代理、鉴权、租户隔离、事件重连及持久化。任何未执行、失败或范围不足的检查均明确记录，不把历史验收当作本次结果。
