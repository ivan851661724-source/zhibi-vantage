# 知彼 Vantage 产品需求文档

版本：v1.4.0 产品评审稿  
日期：2026-10-13  
状态：待产品评审，尚未替代现行冻结版  
适用用户：以独立站和 Shopify 为主的跨境电商卖家

## 背景与用户问题

卖家需要持续了解竞争对手的商品、价格和促销。团队知道部分对手，仍要定期打开多个网站、核对数据、整理变化，再判断哪些变化值得行动。一次查询结果不能替代这项长期工作。

Vantage 为用户建立竞争对象档案，持续检查变化，提供证据和历史记录，并在重要变化出现时通知用户。用户回来继续提问时，系统使用已有上下文，避免重复收集同一批信息。

当前评审指出三个直接影响使用的问题：不同来源的数字不一致时，用户看不出系统为何选择某个值；系统展示“已核实”时，证据和质量检查未必足以支持这一表达；巡检完成后，仍可能漏掉两次检查之间出现的短期变化。相关核查保存在[评审核查记录](#评审核查记录)。

本版围绕这些问题补齐功能行为和验收要求。用户需求、付款意愿和节省时间仍需通过访谈与使用记录验证，不作为已经证实的市场结论。

## 产品目标

用户应能完成以下任务：

- 找到当前品类和市场中值得关注的对象，理解推荐理由和未查清的部分。
- 离线后仍能收到监控结果，区分重要变化、未发现变化和未完成检查。
- 查到每项重要数据的来源、时间和适用条件，发现分歧时知道为何暂不能下结论。
- 基于当前事件和长期历史，理解自己产品与竞品的价格关系。
- 对错误提出反馈，并看到复核、纠正和受影响结论的处理结果。

| 目标 | 观察方式 | 通过标准 |
|---|---|---|
| 首次查询尽快提供可检查的结果 | 从提交需求到首次候选进展、完整或部分结果的时间 | 延续2分钟内展示进展、目标30分钟内交付核验结果或明确缺口；同时检查结果质量 |
| 推荐对象有用且不过度遗漏 | 对照独立调查名单，核验推荐是否合适、漏掉哪些对象 | 按行业与市场设质量底线，发布前完成“决策06” |
| 数据与判断有依据 | 检查来源能否打开，以及内容是否支持对应表达 | 关键数字和判断均可追溯；没有支持的结论不得标为已核实 |
| 变化提醒及时可靠 | 测量误报、漏报、发现时间和送达时间 | 发布前完成“决策06”和“决策08”，不只看通知次数 |
| 减少用户重复工作 | 用户任务所需时间、旧工具使用情况、30天访谈 | 完成“决策17”后统一统计 |

## 用户与使用场景

优先用户是已有稳定业务、约2至5人的跨境卖家团队。用户通常知道部分对手，没有专职竞争情报人员，希望减少重复检查和错过变化的风险。

| 场景 | 用户想完成的任务 | 产品交付 |
|---|---|---|
| 第一次查询 | 找到当前业务值得关注的竞争对象 | 候选名单、推荐理由、相关商品、价格范围和缺口 |
| 加入监控后离线 | 不用每天打开多个网站检查 | 持续巡检、变化提醒、每日摘要 |
| 打开价格变化提醒 | 判断这次变化与自己的价格有什么关系 | 原价与现价、适用规格、证据、进一步分析入口 |
| 一个月后复盘 | 了解谁持续降价、谁频繁促销 | 可比较的历史记录、趋势和未覆盖的时间段 |
| 发现数据不对 | 纠正错误并避免继续被错误结论影响 | 反馈入口、复核进展、更正记录和结果通知 |

## 功能范围与优先级

| 功能 | 首期范围 | 后续范围 |
|---|---|---|
| 发现竞争对象 | 品类、品牌或网址查询；结合市场和参考商品核验；候选转监控 | 扩展行业、市场和可核验渠道 |
| 商品与价格 | 当前公开商品价格、相关产品线、可比规格、商品首次发现 | 更丰富的价格条件和商品关系 |
| 促销监控 | 可验证的折扣、套装、买赠、包邮门槛及订阅优惠 | 按实际覆盖能力扩展 |
| 提醒与摘要 | 变化提醒、检查完成情况、未完成原因、每周工作回执 | 更细的通知偏好和协作 |
| 分析与历史 | 价格位置、历史变化、证据与数据缺口 | 经质量验收的长期行为分析 |
| 反馈与更正 | 用户挑战、复核进展、主动纠错、相关结论更新 | 更完善的团队协作 |

库存、口碑、广告和搜索热度继续按现有优先级逐项验证。能识别一个平台的品牌账号，不代表已经支持该平台所有信号的持续监控。

本期不提供竞品真实销量或交易额预测，不把公开商品价格称为真实平均订单金额，不承诺没有订单证据的实际成交价，不自动执行定价。某个价格区间竞品较少，也不能直接解释为利润空间。

## 页面与用户路径

一级导航沿用工作台、对手、判断、设置。

| 页面 | 主要内容与操作 |
|---|---|
| 工作台 | 最近完成的监控窗口、重要变化、未完成检查、每日摘要和继续提问入口 |
| 对手 | 竞争关系、相关商品、当前数据、品牌时间线、加入或调整监控、查看证据和反馈错误 |
| 判断 | 用户参考商品与价格、分析范围、结果、依据和缺口；从提醒进入时带入原有上下文 |
| 设置 | 市场、币种、时区、监控对象、通知偏好、套餐和账户 |

用户从查询进入候选详情，确认对象后加入监控。通知链接直接打开事件详情。事件详情提供证据、历史和“这对我意味着什么”的分析入口，用户无需重新输入相同业务背景。

## 数据怎样对用户表达

每项重要数据旁边展示可理解的中文说明。详情中提供来源、观察时间、商品规格、市场和必要条件。数据状态与时间信息各自保留，避免把旧的已核实数据当作最新数据。

| 展示名称 | 用户应理解的含义 | 展示与操作要求 | 示例 |
|---|---|---|---|
| 已核实 | 证据支持这项数据在所列条件下成立 | 显示观察时间与条件，支持打开证据；单一来源时说明仅在该来源中核实 | “10月13日14:00，美国站单瓶装标价29美元。” |
| 按已核实数据计算 | 结果由实际取得的数据计算，适用范围取决于样本 | 显示计算所用对象、数量和时间范围；不冒充成交或销量统计 | “已查看12款可比商品，按价格排序后，中间位置的价格为29美元。” |
| 来源有分歧，待核实 | 不同来源给出不同结果，尚未查清原因 | 同时展示相关结果及分歧说明，提供复核进展；无法解释时不强选唯一值 | “两个来源分别显示29和39美元，尚未确认是否属于同一购买条件。” |
| 暂无可靠数据 | 当前未取得足够证据，不能回答 | 说明是访问失败、资料缺失、规格不匹配或暂不支持；提供重试或其他可行入口 | “本次未能完成价格检查，上次成功查看是在10月12日。” |

历史不足时，显示开始观察日期和暂不能回答的问题。例如：“从10月13日开始观察，暂不足以判断连续降价趋势。”资料已过期时，保留原观察时间并提示需要更新。

“已核实”只表示所列事实和条件获得支持，不代表掌握所有顾客的支付价格、品牌销量或经营状况。产品不展示未经真实样本验证的“90%正确”等概率承诺。

## 发现竞争对象

### 输入与需求确认

用户可以输入品类、品牌或网址，并补充市场、参考商品、规格、价格和时间范围。已有信息直接复用；只有缺失信息会改变结果时才追问。系统选择的默认条件应可见、可改。

例如，用户只输入“宠物营养”，如果宠物类型、国家或用途会明显改变候选名单，系统先确认这些条件。结果始终附带实际采用的范围。

### 查询进展与结果

提交后2分钟内展示候选进展，逐步交付核验结果。目标30分钟内返回完整结果或明确的部分结果。部分结果需要说明哪些已经查清、哪些还缺资料，以及为什么停止。

每个候选展示品牌、竞争关系、推荐理由、相关产品线、公开价格范围、平台身份、资料覆盖和加入监控入口。结果区分“符合条件”“还需核实”“不符合当前条件”，并说明原因。

实际符合条件的对象不足5家时返回实际数量。没有找到、查出不匹配和查询失败分别表达，不能统一显示为“0家”。

### 推荐与遗漏

品类、市场、商品用途、人群、价格关系和渠道共同影响推荐。价格接近只能说明一种关系，不能单独证明是直接竞品。

用户可以查看未推荐的重要对象及原因，也可以手动添加已知对手。质量验收同时检查推荐是否合适和是否漏掉重要对象，不能只核验已经找到的名单。

## 加入与管理监控

用户明确点击“加入监控”后，系统展示监控范围、支持信号、首次检查进度和额度占用，并建立当前商品和价格记录作为后续比较起点。

收藏候选不等于加入正式监控。未加入的对象不计入正式巡检和通知承诺。用户调整市场、品类或关注信号后，产品显示新范围及其生效情况，历史记录仍可查询。

新对象缺少历史时，显示“从今天开始观察”。从外部来源补充历史时，显示历史来源和补充时间，避免让用户误以为系统此前一直在监控。

同一公开品牌的资料可在适用条件一致时供不同用户使用。用户自己的价格、偏好、备注和竞争判断始终属于其工作空间，不向其他用户展示。

## 日常巡检与变化提醒

### 检查频率与支持范围

核心信号沿用目标市场时区06:00、14:00、22:00三个巡检周期。上新、促销等具体覆盖以实际通过验收的能力为准。产品展示已支持范围和最近成功检查时间。

系统发现变化后优先复查该对象。访问失败、资料不全或商品规格不匹配时，显示该项检查未完成，不把它写成没有变化。

### 事件详情

| 事件 | 详情需要展示 | 异常与边界 |
|---|---|---|
| 价格变化 | 前后价格、商品和规格、币种、购买条件、前后观察时间、证据 | 更换包装、币种、订阅条件或默认规格时，不直接解释为同商品降价 |
| 商品首次发现 | 商品名称、首次发现时间、已知上市时间、相关产品线、证据 | 改网址、扩大监控范围、迟到抓取或重新上架，不自动视为真实新品 |
| 促销变化 | 促销内容、参与条件、适用商品、已知有效期、证据 | 同一持续活动不因多次检查重复计为多次促销 |

事件区分“首次观察到，正在复核”“变化已确认”“已更正或撤回”。重复看到同一结果不能单独证明商品和购买条件都判断正确。

用户可从详情进入证据和时间线，也可继续询问该事件对自己的产品意味着什么。后续确认或纠正附在原事件下，用户能查到完整变化过程。

### 发现时间与送达承诺

提醒分别说明系统何时发现，以及来源是否能证明实际发生时间。没有可靠发布时间时，不把发现时间写成发生时间。

“当天发生、当天通知”与现有三次检查存在冲突。22:01发生的变化可能次日06:00才被发现。新的发现和送达承诺由“决策08”确定，未确认前不能把当天必达写成已验证能力。

高影响、异常或来源有分歧的变化是否先通知，按“决策10”决定。提醒内容应明确尚未确认的部分。

## 每日摘要与每周回执

每日摘要默认08:00送达，用户可修改时间。摘要明确对应已经完成的监控窗口，不让用户误以为当天后两轮检查已完成。

| 情况 | 用户看到的内容 |
|---|---|
| 有重要变化 | 变化摘要、对象、发现时间、是否已确认、详情入口，以及其他对象的检查情况 |
| 完成检查且未发现需提醒的变化 | 完成窗口、支持范围和“在这些检查范围内未发现符合提醒条件的变化” |
| 部分检查未完成 | 已完成对象和信号、未完成部分、原因，以及是否正在处理 |
| 存在尚未解释的变化或异常 | 待核实事项及进展，不把它隐藏在“没有变化”中 |

所有正式对象的必需检查均完成且资料有效，才允许给出全范围的无变化摘要。页面可以打开或任务已经结束，不代表检查内容完整。

两次巡检之间的短期活动仍可能被遗漏。产品说明支持范围，质量验收单独检查这类漏报。

每周回执展示实际监控对象、有效检查、价格和促销变化、首次发现商品、恢复的异常以及主动更正。重复检查和重试不重复计为独立价值。

## 多来源结果与异常处理

### 为什么采用这项数据

用户在数据详情里能看到采用的值、来源、时间和适用条件；存在其他值时，能看到分歧及处理理由。

不同搜索工具找到同一网页，只算一份内容证据。不同网站转载同一记录，也不能作为独立印证。来源可靠程度应结合具体数据类型、市场、更新时间和历史核验情况，而不是只凭网站名或来源数量。

系统比较的是同品牌、同商品规格、同市场、同购买条件和相近时间的数据。29美元订阅价与39美元一次性购买价可以同时正确；昨天和今天的价格不同，也可能是一条真实变化。

三个来源出现29、29、39时，先检查是否在比较同一条件、是否共享出处。如果仍无法解释分歧，显示“来源有分歧，待核实”，保留相关数据并复核。不能仅因两个数字一致就确定它们正确，也不能取平均数掩盖分歧。

### 异常情况下的产品行为

| 情况 | 产品处理 | 用户需要看到的说明 |
|---|---|---|
| 价格突然大幅变化 | 检查规格、币种和购买条件，必要时复查 | 尚未确认时说明正在核实，避免直接称为真实降价 |
| 页面显示原价和现价 | 分开表达两种价格 | 对比的是哪种价格，是否包含优惠条件 |
| 包装、容量或规格变化 | 匹配同规格，无法匹配时停止直接比较 | “规格不同，暂不能直接比较” |
| 商品目录突然减少 | 先确认资料是否完整 | “部分商品未能检查”，不直接批量通知下架 |
| 缺货后展示其他规格价格 | 不视为原规格降价 | 说明缺货和可售规格变化 |
| 新网址、重新上架或新增监控范围 | 对照历史记录 | 区分首次发现、重新可售与真实上新 |
| 访问、配额或资料读取失败 | 保留上次有效观测，标明本次未完成 | 未完成范围、原因和处理进展 |
| 页面广告或随机推荐变化 | 不作为商品价格或促销变化 | 不生成无关提醒 |
| 高价收藏品、套装、配件或清仓商品 | 按商品用途分类，保留原资料 | 是否参与当前比较及理由 |

用户参考价格不会改变竞品原始资料，也不会决定哪些商品被当作异常删除。被排除的商品及原因应可查询。

## 核心产品与价格分析

### 相关产品线

品牌档案区分主要商品类别、重点推广商品和与当前用户相关的商品。没有销售数据时，不把这些结果称为销量主力。

产品展示推荐的相关产品线、代表商品和依据。首页推荐变化、新增颜色或同一商品被拆成多个页面，不应无理由改变品牌核心业务判断。

资料不足时保留已知商品，说明哪些部分还不能确定。剩余一个看似有力的信号，不足以让整个判断变成高可信结论。

### 用户价格处在什么位置

用户输入或确认参考商品、规格、价格、市场和币种后，产品展示与可比竞品的价格关系。结果说明参与比较的对象、价格条件、样本数量和时间。

普通价格、订阅价、单件与套装价格分别比较。费用或规格信息不齐时，说明限制或暂不比较。商品目录的价格分布不能冒充顾客最常成交的价格。

候选对象范围与针对用户价格的筛选条件分别展示。改变参考价格可以改变价格关系，但不改变竞品原始商品、异常排除和市场总体资料。

分析可以说明某价格区间观察到的竞争对象较多或较少。缺少需求、成本和转化证据时，不进一步给出盈利或最佳定价结论。

### 从提醒继续分析

用户从价格、商品或促销详情点击“这对我意味着什么”后，系统带入该事件、用户参考商品、当前竞争对象和已有历史。

分析返回判断、证据、比较范围和数据缺口。每项重要数字能查到依据；证据只说明当前价格时，不直接推导为“正在打价格战”。相关资料未核实或复核未完成时，只交付已有依据的部分。

## 历史与长期趋势

品牌时间线保留价格、商品、促销、分析、更正和资料缺口。用户可以按对象、信号和时间查看，并从历史记录继续提问。

同商品的价格变化与商品组合变化分开表达。原有商品价格不变，只增加高价商品时，产品说明价格结构发生变化，不写成原商品涨价。

比较促销频率时，采用一致的活动统计规则。扫描次数更多、历史更完整的品牌，不应因此自动被判为促销更频繁。历史中断、开始观察较晚或外部补充资料都应可见。

历史不足或不同时间段无法直接比较时，限制趋势结论并说明原因。新的分析不抹掉旧判断，用户能同时查看当时结果和后续更正。

套餐历史长度与纠错取证需求分别管理。调整可查看历史时，不删除仍用于处理用户挑战和错误复核的依据。

## 用户反馈与主动更正

数据和判断详情均提供“数据有误”和“判断有误”入口。用户可指出错误内容、提供依据，并看到提交成功和后续进展。

挑战提交后，最迟1个工作日返回确认正确、确认错误，或“初步结论、还缺什么证据、下一次更新时间”。不能长期停留在复核中而没有进展。

确认错误后，最迟24小时完成更正或撤回。更正说明原结果、新结果、原因、证据和处理时间。受到影响的提醒、分析和其他用户可见内容应同步处理，不能只修正当前页面。

用户修改自己的偏好可以直接作用于自己的分析。用户提交的公共品牌事实先复核，未核验内容不能立即影响其他用户，也不能直接当作质量评估中的正确答案。

## 隐私与使用边界

用户的经营信息、参考价格、备注和分析范围只在其有权访问的空间内使用。公开品牌资料共享前，应确认身份、市场和数据条件一致。

外部网页中的恶意指令不能改变产品规则、冒充证据或导致经营信息外传。用户打开的证据链接应来自可核验来源，不携带无关私有信息。

品牌同名、经销商、地区站点和不同平台店铺存在歧义时，保留待核实状态，避免错误地共用资料。资料无法合法获取或保存时，产品限制相应能力并说明边界。

## 质量验收与发布条件

### 验证结果是否正确

质量验收使用独立调查和标注的数据，覆盖已推荐、未推荐、无法回答、来源冲突、失败任务和无变化摘要。不能仅检查用户已经看到的成功结果。

用于调整算法的案例与最终验收案例分开。关键结论存在人工分歧时，记录分歧和处理结果；用户偏好与事实错误分别统计。

| 检查对象 | 要验证的结果 |
|---|---|
| 数据准确性 | 当前商品、价格和条件是否与独立核验相符 |
| 来源与证据 | 证据能否打开，内容是否真正支持对应数字和判断 |
| 竞争对象发现 | 找到的对象是否合适，独立调查中的重要对象是否被漏掉 |
| 核心产品 | 产品线名称和代表商品是否符合明确的业务定义 |
| 变化提醒 | 哪些提醒有误，哪些真实变化未被发现，多久发现和送达 |
| 无变化摘要 | 独立检查后是否发现被遗漏的重要变化 |
| 无法回答的情况 | 结果正确程度与可回答范围一起评价，防止靠减少输出提高表面准确率 |
| 长期分析 | 历史缺口、商品组合和观察机会是否导致错误趋势 |
| 品牌资料共享 | 是否误合并身份、泄露用户信息，纠正后是否仍显示旧错误 |

每项正式能力公布前，先确认质量目标、验收范围、所需样本和责任角色。目标值由产品与数据团队在发布评审前决定，见“决策06”；尚未满足条件的能力仅在明确限制的范围内提供。

现有程序检查通过，不能替代真实数据质量验收。来源存在、多个来源一致和无人投诉，也不能单独证明结果正确。

### 上线后持续检查

持续抽查已交付结果、未交付结果、来源分歧、无法回答和无变化窗口。用户纠错用于发现问题，同时保留独立抽查，避免只统计主动投诉的用户。

质量明显下降时，限制受影响能力，保留其他已验证结果，向用户展示相应缺口。访问或成本限制不能悄悄降低已经承诺的检查范围。

## 商业验证

主要收费围绕正式监控对象、市场、支持能力、巡检频率和可查看历史。每月29美元和49美元套餐仍是待验证假设，最终额度和价格结合持续使用价值与服务成本确定。

用户使用30天后，调查是否停止或显著减少至少一套旧工具。结合任务完成时间、通知有用性和历史使用，判断是否减少工作和遗漏。

打开证据、没有提交挑战、打开提醒等行为只作为辅助观察。它们不能直接代表数据正确、用户信任或决策有效。

## 需要产品决定的问题

以下问题仍待评审。推荐方案供产品选择，未确认的承诺和质量门槛不作为已经生效的结论。

| 事项 | 需要决定什么 | 可选方向与影响 | 推荐方向 |
|---|---|---|---|
| 决策01 | 只有一个直接来源时，哪些数据可以标为已核实 | 全部要求多个来源会增加时间和费用；按数据类型准入需要明确范围 | 有直接支持且条件完整的数据允许核实，说明来源与适用范围 |
| 决策02 | 来源分歧时怎样交付 | 暂停结果、展示多值，或在解释后采用某值 | 先展示分歧，未查清时不强选唯一值 |
| 决策03 | 是否向用户展示来源总分或正确概率 | 分数便于比较，但可能制造未经验证的确定感 | 首期展示来源、时间、核验情况和限制，不展示未经验证的概率 |
| 决策04 | 核心产品具体指什么 | 主要目录、重点推广、销量主力和用户相关商品含义不同 | 分开主要产品线与用户相关线，没有销量资料不称销量主力 |
| 决策05 | 何时可以称为直接竞品 | 相似对象发现较容易，真实替代关系需要更强证据 | 分级说明竞争关系和依据 |
| 决策06 | 各能力的准确、误报、漏报及覆盖底线 | 只看总体平均可能掩盖某行业很差；按能力和市场验收更严格 | 按错误影响设置发布底线，同时考虑可回答范围；产品与数据团队发布前确认 |
| 决策07 | 价格比较包含哪些条件和费用 | 普通标价更易取得，实际支付价格需要完整优惠和费用信息 | 首期比较条件明确的公开价格，不承诺真实成交或到手价 |
| 决策08 | 发现和送达的时间承诺 | 修改承诺、增加晚间检查，或提高重点对象频率 | 先明确可验证的发现与送达时限，再评估是否增加检查 |
| 决策09 | 商品提醒默认叫首次发现还是上新 | 首次发现能及时交付，但不能证明实际上市时间 | 缺少可靠上市时间时称首次发现 |
| 决策10 | 未确认的重要变化是否先通知 | 全部先发容易误报，全部等确认会增加延迟 | 按影响和异常风险决定，通知中说明核实进度 |
| 决策11 | 08:00摘要描述哪个时间段 | 前日完整窗口、上次摘要以来或早间检查，含义不同 | 明确完成窗口；有未解决变化时不作全范围无变化表达 |
| 决策12 | 长期趋势怎样比较 | 固定商品反映同品变化，动态目录反映商品结构 | 两类变化分别展示，说明缺口 |
| 决策13 | 证据复核失败时能展示什么 | 保留高可信可能误导，隐藏全部会损失已有可靠信息 | 仅交付已有支持的部分，未验证判断暂停或说明限制 |
| 决策14 | 品牌身份不确定时是否共用资料 | 共用更快，错误合并会影响多个用户 | 不确定身份先核实，优先避免误合并 |
| 决策15 | 用户纠错能否立即影响公共数据 | 即时更新快，未经核验的反馈可能传播错误 | 私有偏好即时生效，公共事实先复核 |
| 决策16 | 初次研究多久停止、哪些缺口可以交付 | 深查提高覆盖但增加等待与费用；早停需要明确说明缺口 | 按问题复杂度提供范围，结果附停止原因 |
| 决策17 | 如何判断用户实际受益 | 打开率易采集，任务时间和工具替代更贴近工作变化 | 结合独立质量抽查、用户任务和30天工具使用调查 |

数据库迁移、搜索供应商替换和其他技术选型在独立工程评审中处理，不纳入本版产品功能决策。

## 发布前必须关闭的P0问题

P0表示阻塞对应能力或承诺。问题尚未关闭时，应限制相关能力，保留其他已有可靠依据的服务。核查来源与技术证据见[评审核查记录](#评审核查记录)。

| 问题 | 对用户的影响 | 产品要求 | 关联决策与验收 |
|---|---|---|---|
| P0-01 多来源缺少统一采信规则 | 看不出为何采用某个数字 | 说明条件与采纳理由，分歧未解释时不强选 | 决策01、02、03；验收01至04 |
| P0-02 证据未充分支持仍可能标为可靠 | 无关引用或复核失败的结果被误当事实 | 只展示获得支持的结论，未验证部分说明限制 | 决策13；验收05、06 |
| P0-03 重复来源和搜索命中被当成独立印证 | 转载和同一网页可能夸大可信程度 | 区分检索路径与独立内容证据 | 决策01、03；验收02、03 |
| P0-04 质量标准与独立验收不完整 | 不知道准确和遗漏程度是否可接受 | 发布前确认独立评估和质量底线 | 决策06；验收07至09 |
| P0-05 噪声与异常处置不完整 | 无关变化被提醒，真实异常可能误删 | 异常分别核实，保留原数据与排除理由 | 决策06、07；验收10、11 |
| P0-06 参考价改变竞品资料筛选 | 改自己的价格后，竞品客观数据也变化 | 参考价不参与原始数据清洗 | 决策07；验收12 |
| P0-07 发现遗漏缺少独立评价 | 名单看起来很准，却漏掉关键对象 | 检查独立调查中的未发现对象 | 决策05、06、16；验收13 |
| P0-08 核心产品和竞争关系定义不清 | 把主推、目录占比或相似当成真实销量和竞争 | 明确名称、依据和关系强度 | 决策04、05；验收14 |
| P0-09 资料少仍可能得到过强判断 | 少数信号造成虚假的确定感 | 信息不足时限制结论，不能只凭高分判可靠 | 决策03、06；验收15 |
| P0-10 先按价格筛选再判断价格 | 结论被筛选条件预先限定 | 明确总体与筛选范围，改变参考价不改客观资料 | 决策05、07；验收16 |
| P0-11 价格可比条件不完整 | 不同包装或购买条件被当同商品比较 | 同规格同条件比较，无法匹配时说明不可比 | 决策07；验收17 |
| P0-12 检查完成被当成没有变化 | 成功检查仍可能漏掉短时活动 | 明确范围，独立核验无变化摘要和漏报 | 决策06、11；验收18、19 |
| P0-13 当天必达与现有频率冲突 | 夜间变化可能次日才发现 | 确认可达成的发现与送达承诺 | 决策08；验收20 |
| P0-14 首次发现或重复检查被过度解释 | 旧商品被称新品，错误结果被重复确认 | 区分发现与上市，并核对商品及条件 | 决策09、10；验收21、22 |
| P0-15 趋势受商品结构和资料缺口影响 | 将目录变化或检查机会误认经营动作 | 同品、商品组合与资料缺口分别说明 | 决策12；验收23、24 |
| P0-16 身份与错误更正可能影响多个用户 | 错误资料复用后仍影响提醒和分析 | 避免误合并，更正所有受影响结果 | 决策14、15；验收25、26 |
| P0-17 外部恶意内容与未核验反馈影响结果 | 数据被伪造，或经营信息泄露 | 不执行网页指令，限制私有信息使用，公共纠错先核验 | 验收27、28 |

## 产品验收场景

| 场景 | 操作或条件 | 期望结果 |
|---|---|---|
| 验收01 | 同规格价格29、29、39，购买条件未齐 | 先核条件，保留分歧，不直接多数票选29 |
| 验收02 | 两个搜索工具找到同一网页 | 可展示检索路径，但不增加独立内容证据数 |
| 验收03 | 两个网站转载同一原始价格记录 | 不因转载增加可靠等级 |
| 验收04 | 相反证据未解释或复核达到限额 | 显示分歧与停止原因，不编造中间值 |
| 验收05 | 官方页面只有欢迎语，却被引用支持价格 | 该价格不能标为已核实 |
| 验收06 | 证据复核超时、漏答或无法完成 | 未验证判断暂停或说明限制，可靠事实仍可查看 |
| 验收07 | 正确性样本为零、待核验或数量不足 | 不显示为100%正确，不通过正式能力发布 |
| 验收08 | 调整规则时用过的品牌又用于最终验收 | 不能当作独立验收结果 |
| 验收09 | 大量查询失败或无法回答，剩余输出很准 | 同时报告可回答范围、失败和错误情况 |
| 验收10 | 页面随机推荐变化，价格不变 | 不发价格变化提醒 |
| 验收11 | 真正大幅降价或存在小众高价商品 | 按商品与证据核实，不仅按高低价删除 |
| 验收12 | 同一目录分别输入参考价50和100 | 原商品与异常排除不变，价格关系可变化 |
| 验收13 | 独立调查中存在未被找到的竞品 | 计入遗漏评价 |
| 验收14 | 商品新增颜色、拆成多个页面或首页换推荐 | 无业务依据时不认定核心业务变化 |
| 验收15 | 只剩一个高分信号或资料极少 | 说明信息不足，不给过强结论 |
| 验收16 | 用户改变参考价格 | 客观资料不重写，筛选范围的变化可解释 |
| 验收17 | 单瓶29与三瓶59、订阅价与普通价 | 匹配条件或说明不可比，不直接认定同品降价 |
| 验收18 | 检查完成但必需资料缺失 | 标明该项未完成，不给全范围无变化摘要 |
| 验收19 | 促销15:00至18:00存在，检查在14:00和22:00 | 独立验收计入遗漏，不用检查成功掩盖漏报 |
| 验收20 | 22:01发生且持续存在的变化 | 按批准的时间承诺评价，不自动声称当天必达 |
| 验收21 | 刚加入监控、改网址、扩大范围或旧商品重上架 | 不自动称真实新品，可展示首次发现及原因 |
| 验收22 | 同一错误结果连续出现两次 | 不只凭重复一致就认定正确 |
| 验收23 | 原商品价格不变，新增高价商品 | 说明商品组合变化，不称原商品涨价 |
| 验收24 | 一个品牌检查更多、另一品牌历史中断 | 比较促销或趋势时说明观测差异和缺口 |
| 验收25 | 同名品牌、经销商、地区站点或不同平台店铺 | 不误合并资料，不确定时先核实 |
| 验收26 | 共享价格或身份被确认错误 | 找到受影响的提醒、分析和用户内容并更正 |
| 验收27 | 网页要求改规则或把经营信息放进外部查询 | 产品规则不变，私有信息不外传 |
| 验收28 | 用户提交未经核验的公共事实纠错 | 不立即影响公共事实或作为正确性答案 |
| 验收29 | 08:00生成摘要，后两轮检查尚未发生 | 显示实际完成窗口，不声称当天全程无变化 |
| 验收30 | 来源故障、限额耗尽或集中检查高峰 | 显示未完成范围与处理进展，不暗中改成没有变化 |

少量场景通过不代表总体准确率达标。正式发布还须满足“质量验收与发布条件”中的独立评估要求。

## 依赖与评审安排

产品优先决定数据准入、来源分歧、质量底线、发现与送达时限、首次发现的名称、每日摘要窗口，以及复核失败如何交付。其他命名、比较范围、长期分析和共享规则随后统一。

每项决定记录选择、理由、参与角色、适用能力和验收条件。产品与数据团队在发布评审前确认质量目标；设计确认用户表达和异常路径，研发与测试验证可达成范围。具体负责人由团队指定，不预设已分配人员或排期。

依赖技术规格更新的产品要求，在对应规格评审后进入实现。本版保持产品评审稿状态，现行冻结版及其权威关系不变。

### 用户观点核查

| 用户观点 | 核查结论 | 新版处理 |
|---|---|---|
| 多源返回不一致时，没有完整的选值依据 | 基本成立。已有冲突、来源分级和去重，但字段之间规则不统一，也没有完整的经验准确率与适用范围 | 建立按字段的采信契约，保留候选值和裁决理由 |
| QA没有任何实际标准 | 表述过强。已有 独立标注评估 方案、准确率样本、样本不足门禁和单测；缺少独立真值、统计验收和完整质量目标 | 区分程序测试、算法评估和生产抽检 |
| 没有唯一可信来源，就无法认定结果 | 需要修正。可以保留多份观测，只有在明确上下文和证据条件下选出当前采纳值；也允许无法裁决 | 用户看到采纳依据、有效时间和未解决分歧 |
| 没有具体噪声和异常规则 | 部分成立。现行规格已列极端价格、币种、规格错配等异常，但触发、处置和误伤验收不完整 | 增加异常处理表和可执行验收场景 |
| 给来源打分有助于判断可信度 | 成立，但评分应按字段、市场和采集方法验证；来源总分不能代替结论核验 | 先使用可解释的质量维度和经验可靠性 |
| 三个来源里两个数字一样，就认定这两个正确 | 不成立。两个来源可能转载、缓存同一记录或共享解析错误，也可能与第三个来源观察的不是同一条件 | 先检查独立性与可比性，再决定是否采纳 |
| Deep Research都会使用统一评分和多数票 | 缺少这样的通用依据。公开实现强调迭代检索、证据和结果评估，具体裁决方法取决于任务 | 采用可检验的证据规则，不把多数票当行业标准 |
| 搜索优化、报警部署和数据库迁移说明这些问题已解决 | 不能据此判断数据质量。本地代码仍可见SQLite与文件存储；生产迁移状态需要部署证据确认 | 性能、运维、存储与数据效度分别验收 |

这里的 Deep Research 要求，指需求明确、可迭代调查、结论有支持证据、缺口可交付、工具调用有边界且过程可追溯。它不要求每轮监控都调用研究模型，也不要求必须采用多智能体。
